# Celestite 路线图

目标架构见 [architecture.md](architecture.md)。

## 第一里程碑：单 host 在线协作（已完成）

以统一 Rust EditorCore 为基础，完成按需 Buffer、文件系统协调和在线协作。OPFS / native 注入普通文件 FileSystem，Rust / WASM 使用一致的编辑与保存契约；server 协作历史仅驻留内存，不做 CRDT 离线编辑。

CRDT 历史驻留内存，host 确认与普通文件保存分别完成；协作只做显式保存。

| 顺序                   | 交付                                                         | 完成标准                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1：内存 host 与 Buffer | 单 Vault 配置、内存协作历史与按需打开                        | 无私有状态库；启动和连接不加载全文；打开时创建或复用 Buffer；重启重新生成历史身份，保留已保存文件，旧历史不能继续同步                                                         |
| 2：文件系统协调        | core 内的磁盘基线、历史分支、细粒度 diff 与保存恢复          | 观察到的连续外部修改从对应磁盘历史生成操作，再合入当前正文；正文与磁盘基线在 core 内一致更新；重复通知及自身写回不产生额外编辑；不确定写回保留证据；保留活动 core、撤销和订阅 |
| 3：server 会话与同步   | 文件监听及主动核对，WebSocket 握手、快照、增量传输与会话约束 | 打开与订阅之间不漏更新；只向当前订阅目标 Buffer 的会话推送；操作关联历史身份和会话；重发不重复提交；失效会话操作被拒绝；监听不隐式加载其他正文                                |
| 4：无头集成验证        | 多个独立 core 连接真实 server                                | 并发编辑、个人撤销、外部修改、乱序更新和文件保存正确；同一进程内重连能取回已接受历史；重启仅保留已保存文件并拒绝旧历史                                                        |
| 5：Web 协作接入        | 远端编辑通过客户端 core，在线状态与断线遮罩                  | 多个 Web 客户端同步编辑；离线禁止打开远端 Vault / 新文档并停止编辑；重连从 host 重建活动会话；整个 Vault 工作区断线遮罩提供重连；未确认输入可导出并明确丢弃                   |

### 协作边界与验收

- 默认 OPFS Vault 独立运行；协作 Vault 由固定 server host 托管，客户端通过 URL 加入，不建立普通目录镜像。
- 每个 VaultInstance 一条 WebSocket，多路传递已打开 Buffer 的增量、目录提示、内存接受确认、保存命令和心跳。
- 首次连接不发送正文；打开 Buffer 才从 host 快照加入。重连按 ID 重新打开当前订阅的 Buffer，使用新的 peer 和个人撤销会话；整批验证路径、删除状态与历史版本再原子切换，提交前失败保留旧会话与期间收到的更新。已提交的快照与后续事件连续交付，维护失败不反转提交结果。
- 远端更新由客户端 core 导入，再通过变化事件增量更新 UI；光标、选区、待确认输入与 IME 组合输入不被整篇替换破坏。
- 断线时遮罩整个 Vault 工作区（文件树与编辑区）并禁止交互；重新连接直接采用 host 历史，清空个人撤销。未确认输入允许导出正文，明确丢弃后重连；不自动重放、核对或合并旧会话修改。
- 已明确拒绝的输入保留正文，可导出并撤回其依赖输入后继续编辑；结果未知时必须明确丢弃后重连。
- 共享保存冲突只提供取消与重试；关闭视图或连接、下载文件不隐式写回共享正文，未确认输入阻止关闭。
- 历史身份变化时明确警告，禁止将旧历史直接导入；迟到回复不污染新会话。
- 创建、重命名、移动、删除在线提交 host，当前历史内文档身份保持稳定；目录变化可发现，未打开文件不建立 CRDT，附件按需读取。
- 文件监听按实际观察到的磁盘快照解释修改，不承诺捕获所有瞬间状态；无法确定保存结果时停止自动推断，保留冲突与恢复材料。
- 外部差异在锁外按固定的行级定位与字符级比较计算；慢任务不阻塞 Vault 编辑和其他文档保存，旧基线或旧路径结果不提交。协调失败对客户端可见并暂停自动写回，相同输入退避重试，支持显式重试。

验收覆盖多客户端编辑、外部保存、server 重启与断线重连的端到端流程。

## 远端分享链接与权限（已完成）

每个 server 进程服务一个 Vault，客户端可连接多个独立 server。多 Vault 集中托管留待 SaaS 场景再考虑。远端以 `https://host/<key>` 连接，API 追加 `/api/v5/...`。宿主启动时提供固定 readonly / edit 链接，readonly 使用 `ro-` 前缀，授权不依赖账号。

| 阶段               | 交付                                                         | 完成标准                                                                                                                                           |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1：链接派生与配置 | 配置文件与 CLI 可选 `share_key`、启动链接输出与 `public_url` | 显式秘密值与相同规范根目录保留链接；省略时每次启动生成临时链接；秘密值轮换同时替换两种链接；公开地址不影响凭证；固定链接不保留历史；无需初始化流程 |
| S2：网络授权       | 基址路由、统一权限、HTTP / WebSocket / 持续订阅              | readonly 拒绝所有修改入口，读取、预览与实时更新可用；宿主退出关闭活动连接；普通请求日志脱敏                                                        |
| S3：客户端连接     | 单 URL 输入、独立连接身份、有效权限与失效交互                | 同库两种链接分别维护实例；权限不混用；重连核对身份与权限；旧链接失效时保留未确认正文及恢复能力                                                     |
| S4：迁移收口       | 调用方、测试、调试入口、示例与当前文档                       | 单进程单 Vault，无配置 ID 或多库注册入口；客户端跨服务连接可用；启动、轮换、重启和只读验证通过；格式与类型检查通过                                 |

## 协作基础收口与成员状态

按职责、交互延迟、成员状态和大库规模分阶段推进。成员指针与选区建立在统一会话和锚点契约上；大库按需加载可独立实施。

| 阶段                               | 交付                                                                    | 完成标准                                                                                                                                                                                                                                       |
| ---------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1：恢复与保存语义（已完成）       | 原子接入 / 重连、拒绝输入恢复、共享保存与关闭                           | 路径复用不依赖快照顺序；失败保留旧会话；明确拒绝与结果未知分开恢复；关闭和下载不隐式保存；未确认输入阻止关闭                                                                                                                                   |
| C2：职责与契约统一（已完成）       | 编辑结果、确认状态、会话生命周期与视图投影契约；迁移旧入口与测试        | core 管理正文、锚点和历史规则；同步会话管理 host 确认与网络状态；UI 管理待确认投影；调用方与测试统一到生产接口，删除被替代的业务实现及兼容入口；退订释放活动路径与预览需求，同会话重开保留 peer 与撤销，关闭缓存不阻碍同路径新历史或重连后重开 |
| C3：编辑与传输调度（已完成）       | 本地编辑与网络确认分离、有界发送与接收队列、回执对账、资源请求隔离      | 高延迟下本地输入与已到达的远端更新继续推进；保存等待指定编辑确认；顺序与依赖正确；慢网络或资源读取不阻塞其他文档；队列超限可见且保留未确认输入                                                                                                 |
| C4：成员光标与选区（待端到端验收） | 临时成员状态、身份与颜色、版本化锚点、CodeMirror 光标与选区、在线成员栏 | 同文档多成员光标与选区正确；覆盖 Unicode、并发删除、待确认投影和 IME；状态可节流合并，不写历史、不影响撤销；离开、断线与重连清除旧状态                                                                                                         |
| C5：同步工作集与规模               | Buffer 订阅生命周期、引用计数与文档卸载、性能指标                       | 关闭视图可停止无用订阅；卸载不丢失已接受但未写回的正文；历史、发送队列与缓存有界；慢客户端不拖住其他客户端；大库和多客户端场景有内存、延迟与吞吐验收                                                                                           |

每阶段补充真实 Worker / WASM / server 的集成验证；协议行为用故障注入覆盖延迟、回执丢失、队列超限与会话替换。性能优化先测量输入接受、host 确认、导入、传输和内存占用，再确定限额。

## EditorCore 与 Buffer 原生 API 收口

EditorCore 与 Buffer 先按 `&self` / `&mut self` 的所有权关系定义原生业务方法，服务请求与平台部署只做外部适配。复用 Loro 的原生能力，不以新增便利包装保留两套公开文本契约。

| 阶段                                     | 交付                                                       | 完成标准                                                                                                                                                                                                 |
| ---------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B0：Editor 所有权（已完成）              | 原生查询与修改方法、外部服务适配                           | 原生调用不依赖 JSON 分发、请求标识或消息版本参数；Worker / IPC 包装取得唯一可变访问并调用同一原生业务；业务 IO 可异步但不改变借用关系；后台结果通过类型化完成接口校验                                    |
| B1：原生模型（已完成）                   | 方法式读写、原生 peer / 不透明版本、字节坐标与稳定 Anchor  | 普通 Rust 编辑不要求回传 base、构造命令 DTO 或转换 peer 字符串；Anchor 查询只返回请求的坐标；范围统一基于 BEFORE 状态，非法边界与失败输入无副作用                                                        |
| B2：效果与撤销（已完成）                 | 精确修改效果、调用方撤销上下文、可选分组与位置恢复         | 显示增量与原始操作分离；仅本地操作上行；并发个人撤销、替换区间和文末位置恢复正确；视图 JSON 不进入文本模型；拒绝与 no-op 不改变撤销分组；元数据按实际持有生命周期回收                                    |
| B3：请求与历史边界（已完成）             | 外部 Worker / IPC / server 适配、UTF-16 转换与集中版本编码 | 消息输入的旧坐标在包装调用边界被校验或映射；跨文档 / 历史和 peer 冲突仍由原生业务拒绝；乱序待依赖的原包可在当前会话保留并继续导入；重复导入不重复修改；准备绑定原副本及未变化状态，提交不替换活动 Buffer |
| B4：调用方收口（功能已完成，性能待验收） | 示例、契约测试、Web 投影与协作流程                         | walkthrough 从最短读写开始；删除被替代的核心命令与刷新锚点表示；真实 Worker / WASM / server 验证编辑、presence、保存与恢复；量化版本编码和全文快照分配，不增加第二份正文历史                             |

## Web 模块收口（已完成）

保持一个应用包，先明确状态与生命周期的所有者；只有稳定边界具有独立消费者时才提取工作区包。

| 阶段         | 交付                                               | 完成标准                                                                                                                                     |
| ------------ | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| W1：状态归属 | 单文档会话、工作区协调、网络收发会话               | 接受基线与待确认投影由单文档会话对账；工作区不维护第二份投影；接收预算覆盖启动与 IME 暂存，断线和替换按传输生命周期释放                      |
| W2：适配边界 | 纯协议值、共享文件能力、独占调用与 Worker 生命周期 | 协议不依赖 UI 或平台句柄；文件转发不重复业务策略；慢 IO 让出消息边界但不破坏 core 独占；派生任务失败不替换已完成命令的结果；启动失败清理资源 |
| W3：视图组合 | 标签、状态、源码扩展与 UI 缓存                     | 视图不依赖全局设置单例；应用统一处理退出和保存策略；CodeMirror 缓存不进入 Vault 运行时；切换、焦点、IME 与个人撤销行为保持一致               |

## Rust / Web 协议单源化

使用一个类型生成器，先删除共享值的手写镜像，再收口必要的表示转换；保留原生所有权 API，不为工具引入领域包装或通用 RPC 框架。

| 阶段               | 交付                                | 完成标准                                                                                                                              |
| ------------------ | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| T1：预览（已完成） | Rust 生成声明、对象式 WASM 计算入口 | 预览任务与结果无手写 TS 镜像，无 JSON 字符串中转；缺省、null、map、字节数组、身份精度和 UTF-16 映射保持；原生与真实 Worker 流程可验证 |
| T2：core 回执      | 类型化协议修改效果与命令结果        | 动态拼装替换为共享协议类型；失败后已接受的 mutation 仍完整交付；新增 Rust 与适配代码计入维护成本，删除被替代入口                      |
| T3：浏览器 IO      | 按需要收口 IO 请求与回复            | 类型化桥能实际删除重复约定，不引入第二份保存或恢复策略；网络历史包、明文恢复格式与授权边界保持                                        |

## 内存历史与明文恢复收口

移除 CRDT 长期存储，普通文件空间与私有恢复空间共用基础 FileSystem 契约；历史只在活动 Buffer 和在线同步中存在。

| 阶段           | 交付                                     | 完成标准                                                                                                                                                                                                                                                                                             |
| -------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1：纯文件 IO  | 平台 FileSystem 与 core 内明文恢复格式   | 平台只实现字节和目录 IO，无历史 load / commit 包装；普通文件和私有恢复区独立注入；远端副本不需要文件或恢复适配器                                                                                                                                                                                     |
| R2：草稿恢复   | 明文草稿、磁盘基线、保存和目录操作意图   | 写回不确定时保留证据；草稿与操作意图跨重启恢复；历史身份和 writer 更新，稳定 instanceId / vaultId 保留；个人撤销不跨重启                                                                                                                                                                             |
| R3：失败与关闭 | recoveryError、checkpoint 与关闭重试     | 编辑不等待恢复 IO，500ms 合并期限不随连续输入延后，慢 IO 不重复排队全库 checkpoint；尝试全部草稿和目录意图，失败停止本轮自动重试且不阻塞其他草稿；恢复错误清除同步到全部相关文档；显式重试不重复编辑；关闭失败保留窗口与 owner；成功才释放恢复区锁                                                   |
| R4：协议与迁移 | v5、调用方和旧数据一次迁移               | 删除历史持久化状态和服务入口；旧私有数据只迁移明文及恢复证据，新格式不写 CRDT；WASM、server、桌面与浏览器集成通过                                                                                                                                                                                    |
| R5：会话职责   | 共用编辑会话、本地文件会话与远端同步会话 | 共用层只串行执行 core、映射输入与交付变更；本地组合输入结束恢复自动保存，只读查询不广播驻留全文；远端接入失败退订，重连提交前失败保留旧会话及未确认屏障，提交后断线采用新快照并保持离线；纯内存 API 无虚拟 FS、无保存计时，直接保存明确拒绝；LF 正文与 CRLF/BOM 物理容量约束贯穿保存、恢复和外部合并 |

## 文档预览实施

预览是通用只读文档源的独立消费者，生命周期不进入 Editor；本地与远端采用同一接口。Notist 原始分析与语义环境为未来语言查询提供共享边界，渲染转换另行派生，不预设增量编译或跨 Worker 的完整 IR 缓存。

| 阶段                | 交付                                                                    | 完成标准                                                                                                                                                                                                                    |
| ------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1：Rust 计算与会话 | Notist / notist-html 计算模块、独立控制器与只读源、类型化任务和状态契约 | `.not` / Markdown 输出 HTML 与诊断；Rust / WASM 共用计算逻辑；正文与版本成对取得，诊断 Unicode 范围正确；编辑、撤销、导入、重命名、关闭重开后的旧任务不能被接受                                                             |
| P2：后台执行        | 独立分析 Worker、平台计时、请求合并、缓存与任务限制、故障重试           | 首次订阅立即分析；连续编辑只保留最新待处理快照；慢分析不阻塞编辑和保存；崩溃、超时、取消订阅和重启后的晚到结果不污染会话；关闭实例释放执行器                                                                                |
| P3：预览界面        | 源码 / 分栏 / 预览模式、ShadowRoot 排版与主题、滚动状态、诊断展示与定位 | 未保存正文可预览；标题、列表、表格、引用和代码块可读；恢复节点可显示；显示模式跨文档与 Vault 共用，刷新恢复；各文档独立保留滚动位置；切换模式保留编辑状态；过期内容明确处于待更新状态，过期诊断不跳转到错误位置；窄屏可切换 |

# Celestite 路线图

目标架构见 [architecture.md](architecture.md)。

## 第一里程碑：单 host 在线协作

以统一 Rust EditorCore 为基础，按以下顺序完成持久化、文件系统协调和在线协作。OPFS / native 注入不同 Backend，Rust / WASM 使用一致的编辑、身份、保存与恢复契约。

**下一步先做每个 Vault 的 host 历史持久化。** 普通文件是历史的磁盘投影，历史提交与文件保存分别确认；首期只做显式保存。

| 顺序                 | 交付                                                        | 完成标准                                                                                                                                                            |
| -------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1：host 持久化       | 每个 Vault 的目录与状态目录配置，历史初始化、恢复与显式重置 | 重启保留 Vault / 文档身份、CRDT 历史、未写回正文及恢复意图；状态缺失或损坏不静默创建新历史；host 提交回执对应持久化版本                                             |
| 2：文件系统协调      | core 内的磁盘基线、历史分支、细粒度 diff 与保存恢复         | 观察到的连续外部修改从对应磁盘历史生成操作，再合入当前正文；历史与磁盘基线原子提交；重复通知及自身写回不产生额外编辑；不确定写回保留证据；保留活动 core、撤销和订阅 |
| 3：server 会话与同步 | 文件监听及主动核对，握手、快照、增量传输、会话约束          | 快照与订阅之间不漏更新；操作关联 Vault / 历史身份和会话；重发不重复提交；未提交的失效会话操作被拒绝；监听覆盖未打开文件                                             |
| 4：无头集成验证      | 多个独立 core 连接真实 server                               | 并发编辑、个人撤销、连续外部修改、重复或乱序更新、保存中断、重启及断线重连完成闭环；客户端收敛，已确认历史可恢复                                                    |
| 5：Web 协作接入      | 远端编辑通过客户端 core，在线状态与修改恢复界面             | 多个 Web 客户端同步编辑；离线禁止打开远端 Vault / 新文档并停止编辑；重连从 host 重建活动会话；未确认操作和 UI 输入可核对、导出或显式恢复                            |

### 协作边界与验收

- 默认 OPFS Vault 独立运行；协作 Vault 由固定 server host 托管，客户端通过 URL 加入，不建立普通目录镜像。
- 每次连接以 host 快照建立活动历史，使用新的写入身份与个人撤销会话；补齐连接期间的更新后才允许编辑。
- 断线后的已打开内容可只读查看、复制。替换会话缓存前隔离未确认操作和 UI 输入；核对已提交但回执丢失的操作，不自动重放旧会话修改。
- 历史身份变化或 host 丢失已确认历史时明确警告并保留恢复材料；新活动会话仍以 host 为准，跨历史操作不直接合并，迟到回复不污染新会话。
- 创建、重命名、移动、删除在线提交 host，文档身份保持稳定；全库发现与后台补齐覆盖未打开文件，附件按需读取。
- 文件监听按实际观察到的磁盘快照解释修改，不承诺捕获所有瞬间状态；无法确定保存结果时停止自动推断，保留冲突与恢复材料。

完成无头验证后接入 Web，再以多客户端编辑、外部保存、server 重启和断线恢复的端到端流程验收第一里程碑。

## 第二里程碑：语言能力

在线协作闭环后接入 Tree-sitter 和 LSP，先以 JSON 验证完整流程。

| 阶段        | 交付                                 | 完成标准                                                             |
| ----------- | ------------------------------------ | -------------------------------------------------------------------- |
| Tree-sitter | 版本化增量解析与高亮                 | Unicode 坐标正确，旧结果不覆盖新正文，资源失败仍可编辑               |
| LSP         | 工作区、文档同步与 JSON Web 语言服务 | 未保存正文参与诊断、补全、hover、定义跳转和格式化                    |
| 收口        | 语言资源重载、故障恢复与集成验证     | 重载保留编辑状态，服务故障不阻断保存，多客户端正文更新可驱动语言能力 |

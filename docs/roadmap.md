# Celestite 路线图

目标架构见 [architecture.md](architecture.md)。

## 第一里程碑：单 host 在线协作（已完成）

以统一 Rust EditorCore 为基础，按以下顺序完成持久化、文件系统协调和在线协作。OPFS / native 注入不同 Backend，Rust / WASM 使用一致的编辑、身份、保存与恢复契约。

普通文件是历史的磁盘投影，历史提交与文件保存分别确认；首期只做显式保存。

| 顺序                 | 交付                                                         | 完成标准                                                                                                                                                            |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1：host 持久化       | 单 Vault 的目录与状态目录配置，历史初始化、恢复与显式重置    | 重启保留 Vault / 文档身份、CRDT 历史、未写回正文及恢复意图；状态缺失或损坏不静默创建新历史；host 提交回执对应持久化版本                                             |
| 2：文件系统协调      | core 内的磁盘基线、历史分支、细粒度 diff 与保存恢复          | 观察到的连续外部修改从对应磁盘历史生成操作，再合入当前正文；历史与磁盘基线原子提交；重复通知及自身写回不产生额外编辑；不确定写回保留证据；保留活动 core、撤销和订阅 |
| 3：server 会话与同步 | 文件监听及主动核对，WebSocket 握手、快照、增量传输与会话约束 | 快照与订阅之间不漏更新；操作关联 Vault / 历史身份和会话；重发不重复提交；未提交的失效会话操作被拒绝；监听覆盖未打开文件                                             |
| 4：无头集成验证      | 多个独立 core 连接真实 server                                | 并发编辑、个人撤销、连续外部修改、重复或乱序更新、保存中断、重启及断线重连完成闭环；客户端收敛，已确认历史可恢复                                                    |
| 5：Web 协作接入      | 远端编辑通过客户端 core，在线状态与断线遮罩                  | 多个 Web 客户端同步编辑；离线禁止打开远端 Vault / 新文档并停止编辑；重连从 host 重建活动会话；整个 Vault 工作区断线遮罩提供重连；未确认输入可导出并明确丢弃         |

### 协作边界与验收

- 默认 OPFS Vault 独立运行；协作 Vault 由固定 server host 托管，客户端通过 URL 加入，不建立普通目录镜像。
- 每个 VaultInstance 一条 WebSocket，多路传递文档增量、目录状态、提交确认、保存命令和心跳；host 历史提交后才确认与广播。
- 每次连接以 host 快照建立活动历史，使用新的写入身份与个人撤销会话；补齐连接期间的更新后才允许编辑。整批验证最终目录、删除状态与历史版本再原子切换，路径复用与初始化顺序无关；失败保留旧会话。
- 远端更新由客户端 core 导入，再通过变化事件增量更新 UI；光标、选区、待确认输入与 IME 组合输入不被整篇替换破坏。
- 断线时遮罩整个 Vault 工作区（文件树与编辑区）并禁止交互；重新连接直接采用 host 历史，清空个人撤销。未确认输入允许导出正文，明确丢弃后重连；不自动重放、核对或合并旧会话修改。
- 已明确拒绝的输入保留正文，可导出并撤回其依赖输入后继续编辑；结果未知时必须明确丢弃后重连。
- 共享保存冲突只提供取消与重试；关闭视图或连接、下载文件不隐式写回共享正文，未确认输入阻止关闭。
- 历史身份变化时明确警告，禁止将旧历史直接导入；迟到回复不污染新会话。
- 创建、重命名、移动、删除在线提交 host，文档身份保持稳定；全库发现与后台补齐覆盖未打开文件，附件按需读取。
- 文件监听按实际观察到的磁盘快照解释修改，不承诺捕获所有瞬间状态；无法确定保存结果时停止自动推断，保留冲突与恢复材料。
- 外部差异在锁外按固定的行级定位与字符级比较计算；慢任务不阻塞 Vault 编辑和其他文档保存，旧基线或旧路径结果不提交。协调失败对客户端可见并暂停自动写回，相同输入退避重试，支持显式重试。

验收覆盖多客户端编辑、外部保存、server 重启与断线重连的端到端流程。

## 远端分享链接与权限（已完成）

每个 server 进程服务一个 Vault，客户端可连接多个独立 server。多 Vault 集中托管留待 SaaS 场景再考虑。远端以 `https://host/<key>` 连接，API 追加 `/api/v1/...`。宿主启动时提供固定 readonly / edit 链接，readonly 使用 `ro-` 前缀，授权不依赖账号。

| 阶段               | 交付                                                                     | 完成标准                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1：链接派生与配置 | 配置文件可选 `share_key`、纯 CLI 必传秘密值、启动链接输出与 `public_url` | 配置文件缺省时已有历史自动补齐；纯 CLI 缺少秘密值时拒绝启动；重启和改名保留链接；秘密值轮换同时替换两种链接；公开地址不影响凭证；无分享初始化及动态管理流程 |
| S2：网络授权       | 基址路由、统一权限、HTTP / WebSocket / 持续订阅                          | readonly 拒绝所有修改入口，读取、预览与实时更新可用；宿主退出关闭活动连接；普通请求日志脱敏                                                                 |
| S3：客户端连接     | 单 URL 输入、独立连接身份、有效权限与失效交互                            | 同库两种链接分别维护实例；权限不混用；重连核对身份与权限；旧链接失效时保留未确认正文及恢复能力                                                              |
| S4：迁移收口       | 调用方、测试、调试入口、示例与当前文档                                   | 单进程单 Vault，无配置 ID 或多库注册入口；客户端跨服务连接可用；启动、轮换、重启和只读验证通过；格式与类型检查通过                                          |

## 协作基础收口与成员状态

按职责、交互延迟、成员状态和大库规模分阶段推进。成员指针与选区建立在统一会话和锚点契约上；大库按需加载可独立实施。

| 阶段                         | 交付                                                                    | 完成标准                                                                                                                                       |
| ---------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| C1：恢复与保存语义（已完成） | 原子接入 / 重连、拒绝输入恢复、共享保存与关闭                           | 路径复用不依赖快照顺序；失败保留旧会话；明确拒绝与结果未知分开恢复；关闭和下载不隐式保存；未确认输入阻止关闭                                   |
| C2：职责与契约统一           | 编辑结果、确认状态、会话生命周期与视图投影契约；迁移旧入口与测试        | core 管理正文、锚点和历史规则；同步会话管理 host 确认与网络状态；UI 管理待确认投影；调用方与测试统一到生产接口，删除被替代的业务实现及兼容入口 |
| C3：编辑与传输调度           | 本地编辑与网络确认分离、有界发送与接收队列、回执对账、资源请求隔离      | 高延迟下本地输入与已到达的远端更新继续推进；保存等待指定编辑确认；顺序与依赖正确；慢网络或资源读取不阻塞其他文档；队列超限可见且保留未确认输入 |
| C4：成员指针与选区           | 独立的临时成员状态通道、成员 / 会话身份、core 锚点接口、CodeMirror 展示 | 同文档多成员光标与选区正确；覆盖 Unicode、并发删除、待确认投影和 IME；状态可节流合并，不写历史、不影响撤销；离开、断线与重连清除旧状态         |
| C5：同步工作集与规模         | Catalog 与正文加载分离、活动文档优先、后台补齐与文档卸载、性能指标      | 首次交互不等待整库正文；未打开文件变化仍可发现；历史、发送队列与缓存有界；慢客户端不拖住其他客户端；大库和多客户端场景有内存、延迟与吞吐验收   |

每阶段补充真实 Worker / WASM / server 的集成验证；协议行为用故障注入覆盖延迟、回执丢失、队列超限与会话替换。性能优化先测量输入接受、host 确认、导入、传输和内存占用，再确定限额。

## 第二里程碑：语言能力

Tree-sitter 覆盖 Notist 原生正文、声明与 Markdown 前端；LSP 先以 JSON 验证完整流程。

| 阶段        | 交付                                 | 完成标准                                                                                                                   |
| ----------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Tree-sitter | 版本化增量解析、高亮、嵌套语言与折叠 | `.md`、`.markdown`、`.nmd`、`.notmd`、`.not`、`.notc` 使用对应语法；Unicode 坐标正确，旧结果不覆盖新正文，资源失败仍可编辑 |
| LSP         | 工作区、文档同步与 JSON Web 语言服务 | 未保存正文参与诊断、补全、hover、定义跳转和格式化                                                                          |
| 收口        | 语言资源重载、故障恢复与集成验证     | 重载保留编辑状态，服务故障不阻断保存，多客户端正文更新可驱动语言能力                                                       |

## 文档预览实施

预览基于统一 core 的版本化正文与任务契约，独立于 Tree-sitter 和 LSP 推进；本地与远端采用同一客户端预览接口。

| 阶段                | 交付                                                                         | 完成标准                                                                                                                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1：Rust 计算与会话 | Notist / notist-html 计算模块、core 订阅与任务生命周期、类型化任务和状态契约 | `.not` / Markdown 输出 HTML 与诊断；Rust / WASM 共用计算逻辑；正文与版本成对取得，诊断 Unicode 范围正确；编辑、撤销、导入、重命名、关闭重开后的旧任务不能被接受                                                             |
| P2：后台执行        | 独立分析 Worker、平台计时、请求合并、缓存与任务限制、故障重试                | 首次订阅立即分析；连续编辑只保留最新待处理快照；慢分析不阻塞编辑和保存；崩溃、超时、取消订阅和重启后的晚到结果不污染会话；关闭实例释放执行器                                                                                |
| P3：预览界面        | 源码 / 分栏 / 预览模式、ShadowRoot 排版与主题、滚动状态、诊断展示与定位      | 未保存正文可预览；标题、列表、表格、引用和代码块可读；恢复节点可显示；显示模式跨文档与 Vault 共用，刷新恢复；各文档独立保留滚动位置；切换模式保留编辑状态；过期内容明确处于待更新状态，过期诊断不跳转到错误位置；窄屏可切换 |
| P4：导航与验证      | 同文档片段、Vault 内及外部链接、性能测量与集成验证                           | 链接按文档目录解析且不越出 Vault；跨文件导航正确；不存在的目标有可见反馈；长文档、表格、嵌套列表及未闭合输入完成编辑预览闭环；分别测量分析、HTML 生成、传输及 DOM 更新耗时                                                  |
| 远端预览接入        | 客户端 core Worker、host 快照与条件保存回执、复用预览 UI                     | 未保存正文、个人撤销、分栏定位与滚动同步在远端可用；只读正文可预览；文件移动保持身份；冲突保留修改；断线暂停编辑并保留正文，重新认证核对历史身份                                                                            |

首期采用全量分析和整体 HTML 更新。分析任务不等待文件保存；预览优先展示 core 已接受正文，待确认输入的即时预览另行定义投影版本。调度参数依据分阶段性能测量调整。

### 分栏定位与同步

先完成节点范围的定位与同步，再推进字符级映射；源码映射与增量分析分别实施。

| 阶段             | 交付                                                      | 完成标准                                                                                                                                                                                                          |
| ---------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P5：输出源码映射 | renderer 的可选映射输出、内部节点标识、版本化 UTF-16 范围 | `.not` / Markdown 的标题、段落、列表、表格、代码块和恢复节点关联到实际输出；源码不能伪造标识，透明节点与空范围有明确回退；HTML 与映射共用任务身份、版本校验及容量限制                                             |
| P6：双向点击定位 | 源码到预览、预览到源码、目标短暂高亮                      | 分栏保持模式，已可见目标保留视口，屏外目标只移动到可见位置；长范围起点可见时不滚到末尾；链接仍可导航，拖选文字不跳转；Unicode、语法标记和恢复内容可按范围定位；过期映射及待确认输入不定位；程序定位不形成往返循环 |
| P7：连续滚动同步 | 可关闭的双向分栏同步、内容锚点插值、布局重测量            | 标题高度、自动换行、折叠、嵌套列表、表格与长代码块下内容保持对应；点击后的滚动从当前两侧视口接续；一侧用户操作驱动，跟随滚动不抢焦点、不改选区、不回弹；HTML 更新和调整宽度后重建锚点，旧版本坐标不被重放         |

字符级精确定位在范围映射闭环后推进，以转义、实体、空白归一化和生成内容的显示文本映射为完成标准。

图片与其他附件、公式排版、代码高亮、DOM 局部更新和增量分析分别推进。附件扩展以只读资源查询和 Blob URL 生命周期为完成标准，不隐式保存正文；增量方案根据耗时分布选择推进顺序，并保留全量回退。

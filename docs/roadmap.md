# Celestite 路线图

目标架构见 [architecture.md](architecture.md)。

## 下一个里程碑

**CRDT + Rust EditorCore + 单 host 协作 + Tree-sitter 高亮 + LSP。**

| 阶段            | 交付                                                   | 完成标准                                                             |
| --------------- | ------------------------------------------------------ | -------------------------------------------------------------------- |
| A：统一 core    | 注入 Backend 的 EditorCore，统一编辑、身份、保存与恢复 | OPFS / native 使用同一业务，Rust / WASM 契约一致，故障不丢已提交历史 |
| B：单 host 协作 | host 目录服务、客户端 core、增量同步与持久化确认       | 两个客户端编辑收敛、个人撤销独立，断线只读且保留修改，重连补齐       |
| C：Tree-sitter  | 版本化增量解析与高亮，JSON 试点                        | Unicode 坐标正确，旧结果不覆盖新正文，资源失败仍可编辑               |
| D：LSP          | 工作区、文档同步、JSON Web 语言服务                    | 未保存正文参与诊断、补全、hover、定义跳转和格式化                    |
| E：收口         | 语言资源重载、故障恢复与集成验证                       | 重载保留编辑状态，服务故障不阻断保存，完整编辑闭环通过               |

先完成 A；文档与工作区事件稳定后，B、C、D 可分别推进，最后完成 E。

## 首期范围

- 默认 OPFS Vault 保持独立；协作 Vault 由固定 server host 托管，客户端通过 URL 加入。
- 客户端拥有私有历史，不建立普通目录镜像；确认断线后只读，已有修改在重连时补齐。
- 目录操作在线提交 host；全库发现与后台补齐覆盖未打开文件，附件按需读取。
- 本机历史、host 历史和文件保存分别确认；外部冲突、身份变化及拒绝操作保留已有修改。

## 后续方向

Tauri native core 与 IPC、Vim、完整离线编辑、协作目录镜像、Catalog CRDT / P2P、富文本、更多语言，以及工作集和历史压缩。

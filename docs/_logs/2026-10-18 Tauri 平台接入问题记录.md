# Tauri 平台接入问题记录

日期：2026-10-18。本文记录桌面平台接入中发现的问题、处理依据及验证边界，内容自包含，不依赖外部文档的后续修改。

## 接入设计

一个桌面 VaultInstance 由原生运行时持有一个 EditorCore，桌面 WebView 复用既有界面、输入投影和服务包装。EditorHost 保留回执交付、坐标基准适配、计时与网络确认编排；保存、历史准入、个人撤销和文本身份的业务规则仍只有 Rust core 一份。IPC 使用既有 EditorAdapter，同样在命令失败时交付此前已接受的 mutation。

native 文件能力与持久 Backend 独立成库，server 和 desktop 直接调用。server 的分享凭证、在线成员和宿主会话保持在 server；不为复用整个 server 服务层引入桌面依赖。桌面私有历史与普通目录分开，远端连接使用 native 内存副本；远端的 WebSocket 与因果确认仍复用既有会话包装。

## 发现与处理

### 桌面运行时不需要独立 crate

初次接入将桌面会话和监听另抽成库，但这些模块只有 Tauri 应用一个消费者；独立运行测试并不要求独立 crate。2026-10-19 将运行时移回根应用库的 `src/runtime`，原集成测试改为应用库内部测试，目录基准改为显式启用的 ignored 测试。server 与桌面共同使用的文件、package 与持久存储能力继续由 `celestite-native` 提供。

下文的既有示例与验收命令保留执行时的记录。迁移后的目录基准使用 `CELESTITE_BENCH_VAULT="$HOME/Files/Vault" cargo test -p celestite --lib runtime::tests::measure_open -- --ignored --exact --nocapture --test-threads=1`，只运行指定基准，避免其他测试干扰进程监听计数。

### server 后端没有桌面恢复语义

已有 server 后端的 load 为空、commit 不写历史，目录意图也只驻留内存。直接用于桌面会失去未保存草稿和目录操作恢复。新增持久 native Backend，以应用私有目录中的稳定身份、不可变增量 journal 和原子 head 为提交点，使用进程锁限制并行所有者。seed、已保存正文和磁盘基线存为不可变对象，避免每次键入重复写完整基线。

### WebView 不能依赖浏览器 Service Worker 资源服务

原组件加载依赖 Service Worker 提供保留相对路径的 ESM 和 WASM 资源。桌面自定义 origin 不保证支持该能力。native 端登记有界、不可变的组件字节快照，通过专用 URI scheme 提供正确 MIME；URL 只定位已登记字节，不映射普通磁盘路径。Browser 保留原 Service Worker 流程。

### 关闭失败可能留下半关闭界面

原工作区 close 使用忽略错误的聚合，并在操作前标记 disposed；直接用于系统关闭会丢失失败反馈。仅将异常继续抛出仍不足以解决多个实例部分关闭的问题。桌面采用两阶段关闭：先冻结并排空 UI 输入、完成本地保存和远端发送确认，再由 native 原子确认所有 owner 的历史提交，全部成功才释放。失败恢复交互，不提前销毁其他实例。 管理器在开始准备时也同步冻结新连接、目录选择、切换和移除入口，并等待此前已接受的整段操作结束；只等待当时的 core 或连接 promise 会漏掉尚停留在目录选择器中的操作，让新实例错过关闭屏障。

### WebView 重载与本机所有者的寿命不同

整页刷新会重建前端，却不会退出 native 进程。同一目录再次创建 core 会与原 owner 的锁冲突，并遗留旧预览订阅。按规范目录幂等复用本机 owner；前端以独立代次接入，代次变化清理旧预览任务和易失远端会话，保留本机正文历史与个人撤销。清理必须重建预览控制器，同时丢弃待发事件并重置序号；仅清空订阅会让新 WebView 从大于 1 的序号开始，被客户端当作消息缺失。

### 路径表示存在平台假设

已有预览资源以字符串开头的 `/` 判断绝对路径，而 wasm32 的标准库路径语义也与 native 不同。Windows 盘符、UNC，以及跨平台客户端连接另一平台 host 都需要统一资源身份。该问题在接入期间单独验证并修复；文档的 Vault-relative 路径规则保持不变，不能通过放宽文件路径校验处理编译资源身份。

### 开发命令没有使用 Web 工作目录

根 Tauri 配置的前端 hook 未指向 Web 包，桌面入口仍为模板命令。Web 包的 CLI 先切换到仓库根目录定位 Tauri 配置；hook 使用显式 `cwd: web`，避免 CLI 默认把根配置的父目录当作前端目录。删除模板命令，注册原生编辑、预览、选择目录、导出和应用配置接口。

### IPC 形状与原生 URL 编码必须用真实边界验证

设置适配器一度把 JSON 对象预先编码为字符串，native 写入边界要求对象，因此实际配置和连接无法保存；改为对象直接跨 IPC，由存储层序列化。组件 URL 的第一版使用 Tauri 对整个路径编码的转换器，导致斜杠变成转义字节，相对 ESM 和 WASM 会丢掉 scope / digest 父目录；改为只取协议 origin，逐路径段编码并保留分隔符。

正常关闭会清理当前页的组件快照，整页重载也必须按窗口清理上一页的 scope，否则旧快照持续占用缓存限额。原生退出事件必须同时覆盖用户 Quit 和程序请求，只有全部 native owner 成功提交后才设置允许退出；窗口关闭保护在 JS 监听就绪前也由 native 承担。

### 可重试失败不能提前拆掉派生消费者

首次实现单个连接关闭时，先销毁 PreviewHost，再执行可能失败的 native owner 释放；释放失败后正文虽保留，预览却无法重新订阅。单连接关闭也改为先完成可失败的提交和释放，再进行纯 JS 拆卸。窗口统一关闭则先暂停并排空派生调度，native 成功后不再发 core / preview IPC。

设置写入的临时 IO 错误还暴露了 flush 只抛旧错误、不重新写入的问题。关闭时的 flush 现可重试实际失败或尚未完成的写入；首次读取失败时保留未知原文件，不用空配置覆盖。

### 退出确认与新会话创建必须串行

runtime 的 shutdown 与 open 各自加锁仍不足够：旧 shutdown 释放 owner 后，新 open 可能创建 owner 并清除退出许可，随后旧 shutdown 又发布许可。应用层以同一个生命周期锁包住会话创建、shutdown 与退出许可发布，避免新 owner 被旧确认放行。

### 桌面来源与系统外链有独立边界

server 的严格来源名单原先只接受 HTTP(S)，Linux / macOS 的打包客户端使用 `tauri://localhost`，因此加入精确的本地桌面 Origin 支持；仍拒绝 `null`、任意自定义协议及带路径的来源。Windows 使用 `http://tauri.localhost`，开发模式使用 Vite HTTP Origin。HTTP 和 WebSocket 保持同一分享权限检查。真实 Linux WebView 的远端验收也启用了只允许 `tauri://localhost` 的名单，确认实际客户端来源可以通过，而非仅用模拟请求验证。

core 允许的协议相对链接在自定义 origin 下不能直接交给系统；桌面先以 HTTPS 规范化这类链接并统一 URL scheme 大小写，FTP 则加入明确的 opener scope。macOS 构建产物先归档为 tar.gz，避免 CI 上传目录时丢失可执行权限与符号链接。

### 原生拖放处理会拦截已有文件树交互

Tauri 默认安装原生 drag/drop handler，Windows 的 WebView2 会因此失去前端 HTML5 拖放事件。现有文件树的导入与移动使用 HTML5 协议，窗口显式关闭这层原生 handler，沿用同一套拖放交互；不并列维护第二套原生拖放业务。

### Nix 开发环境没有提供应用包

原 flake 仅输出开发壳，手工生成的调试 deb 也不会自动携带运行环境配置。新增桌面、Web 资源和启动入口；前端与 Rust 依赖分别构建，原生阶段只嵌入已经生成的静态资源。Bun 依赖采用固定哈希、包含已声明补丁的快照，禁止安装生命周期脚本，实际编译不访问网络。

锁定 nixpkgs 的 wasm-bindgen CLI 为 0.2.127，项目绑定格式要求 0.2.129；为后者单独固定源码与 Cargo vendor 哈希，并让构建与开发壳显式使用它。Tauri hook 会传播 nixpkgs 自带的 Cargo，需要覆盖为项目 nightly，避免在同一构建中混用两套 Cargo；依赖构建与最终构建还要统一 release strip、target linker、C/C++ 编译器和 GTK hook 环境，否则 Cargo 会重新编译依赖。

Linux 包使用与 WebKitGTK 4.1 实际 GTK3 依赖对应的 GApps wrapper，提供 GIO TLS、GSettings、GStreamer 和 NVIDIA 环境默认值；opener 通过 PATH 查找 `xdg-open`，wrapper 也必须提供 `xdg-utils`。运行不再依赖开发壳的临时变量。Darwin 输出安装为应用 bundle，并提供命令行启动入口。当前锁定 Bun 的平台范围限定了三个 flake system：x86_64-linux、aarch64-linux、aarch64-darwin。

### 开库同步建立递归监听会展开库外源码树

2026-10-19 排查 `~/Files/Vault` 打开缓慢：普通树约 2.22 万文件、4208 个目录，但默认递归 watcher 跟随 `.direnv/flake-inputs` 的符号链接，把库外源码树也展开为 80514 个目录监听。开库等待全部注册完成，文件树和文档尚未开始显示。

监听改为独立后台任务，只使用单目录注册；开库异步登记根与父目录锚点，恢复文档按父目录入队。文件树继续按展开目录枚举，编辑与预览共用 IO 前的观察屏障，用户请求优先于恢复队列，不遍历未访问子树。普通符号链接拒绝跟随，显式 package 同时观察别名、实际目标及缺失目标的现存祖先，覆盖链接改指向与目标晚到的情况。

新观察范围和重新注册发出一次保守提示，窗口聚焦也核对工作集；定时与聚焦请求有界合并。已访问目录替换后重建监听，监听后端失败重试并保持文件读写可用。根身份必须从保留的目录句柄比较，不能重新打开当前路径作为身份；Vault 根被替换时明确报失联并保留草稿，不让旧句柄与新路径对应不同目录。

基准仅使用临时私有历史和根目录枚举，不修改用户 Vault。改动前后各用独立进程交替测量三次，未主动清除系统缓存：原生开库中位数从 1942.10 ms 降到 39.54 ms，目录监听数从 80514 降到 2；根目录枚举中位数分别为 0.34 ms、0.38 ms。这些数字不包含 WebView 启动和绘制。仓库提供 `measure_open` 示例重复测量。

### 外部文本差分不能直接信任空侧坐标

恢复文档的外部变化回归暴露已有差分错误：`before restart` 更新为 `external after restart` 后，接受正文成为 `xternal aefter restart`；最小输入 `ba` 到 `aab` 也会错误生成 `aba`。问题不依赖重启或文件监听，固定依赖中的差分压缩会调整插入 / 删除操作，却留下错误的空侧索引。

两级差分改用相等区间之间的空隙生成修改，保留已确定的字符对齐与历史身份；导出操作前验证分支正文与目标一致。回归覆盖 ASCII、整行、Unicode、恢复快照与历史分支，未升级算法依赖或退化为整体正文替换。

## 剩余边界

- 外部程序不参与 Celestite 的锁，文件 revision 检查到最终 rename 之间仍有竞争窗口；临时文件写入和原子替换可以保全失败前的旧文件，不能把跨程序竞争变成硬件事务。
- journal 积累问题已在 2026-10-19 的基础 FS 与草稿恢复调整中移除：不再写入持久 CRDT journal，旧数据只作一次性草稿迁移读取。
- native 分析任务的超时撤销结果适用性，不能抢占已经运行的 Rust 计算；执行并发必须有界，防止重复重试积累无限任务。需要可强制终止的分析执行器时，应使用独立进程。
- 对于已经开始且结果未知的投影写入，如果磁盘随后出现既非旧基线也非本次目标的第三状态，core 继续保留不确定写入意图并拒绝无证据恢复。现有界面可导出正文，尚无专门的第三状态核对与恢复流程；不能通过放宽普通重试或自动覆盖绕过此证据边界。
- 组件模块沿用受信任扩展契约，与应用同域执行，在桌面也可以调用 native IPC。ShadowRoot 和组件资源 URI scheme 都不提供代码沙箱；支持不受信任组件需要独立执行域与能力受限的消息协议。
- 当前环境能够验证 Linux 原生构建和 WebView。Windows 与 macOS 的安装包、系统权限和原生对话框仍需要对应系统验收，不能用 Linux 编译或模拟 IPC 替代。

### 2026-10-19 原生能力与平台接口收敛

进一步审查发现，原生库只有文件 IO 和 package 授权由 server 与桌面共用；持久 NativeBackend 及原子元数据写入仅由桌面使用。将全部原生能力另设 crate 没有必要，也使 server 专用的 HTTP 请求类型和文件事件类型进入共享 API。此次将原生 Backend、文件 IO 和存储辅助归入 core 的 backend::native，将包授权归入 preview::native，通过 native feature 和非 Wasm 目标条件隔离依赖；server 请求与事件类型归还 server，内部 JSON 读取不再公开，旧 crate 与导入路径删除。

前端的公共接口还继承了 WASM 字符串 ABI 和 Worker 消息形状，导致 native 反复 JSON 编解码、模拟预览消息和资源回包。此次 CorePort 改为对象式参数与回复，字符串转换只留在 WASM 适配器；预览统一使用异步执行与取消信号，浏览器适配器管理真实 Worker，native 直接执行共享资源循环和 IPC。同一 WebView 内的手写消息总线改用标准 MessageChannel，并合并重复清理入口与单纯转发函数。会话所有权、IME、关闭确认、监听屏障和根目录身份检查继续保留各自职责。

后续将 Backend 中的实例身份、ID 分配和时钟职责归回 core：宿主从持久 manifest 取得身份后显式传给 EditorCore，内存后端只保存历史；core 使用支持 JS 的 UUID v4 与跨平台 epoch 时钟，确定性测试通过简单时钟闭包控制时间。浏览器 `newId` 桥删除，`cap-std`、`same-file` 和 `blake3` 继续由 native feature 与目标平台隔离。

### 2026-10-19 基础 FS 与草稿恢复

原 Backend 同时承担文件操作、CRDT 历史存储和恢复语义，要求浏览器与原生实现重复维护业务记录。项目只支持在线协作，重连不会重放离线编辑，因此跨重启保存 CRDT seed、更新和版本没有用途。平台接口改为 FileSystem 的 stat、read_dir、read_file、write_file、mkdir、rename、remove；core 分别持有用户文件和私有恢复目录的 FS 能力，自行管理正文草稿、磁盘基线、写入状态与目录操作意图。旧 Backend、HistoryStore 和提交确认包装删除，协议同步升为 v5。

最初逐次编辑写完整草稿会让大文件输入等待 JSON 编码和磁盘同步。改为记录首次待写时间并在 500ms 内合并写入，连续输入不推迟期限；保存、重命名、删除和关闭前强制完成必要的恢复写入。恢复写入失败单独报告，已接受的输入仍可继续编辑，避免重新引入历史提交确认。

原生私有恢复目录继续使用独占锁和原子发布，并拒绝位于用户 Vault 内的恢复目录，包括经过符号链接指向库内的目录。Linux、Android 和 Apple 系统的 rename 使用系统原子 no-replace；其他原生平台仍沿用检查后重命名，外部程序并发创建目标时存在竞争窗口，需对应系统补齐原子原语后才能提供同等保证。

### 2026-10-19 文件所有者与协作副本

继续审查发现，公共 EditorHost 实际内置了本地文件的打开、保存、恢复计时器与文件操作；远端会话通过覆盖这些方法复用执行队列，还要抵消 core 为无文件副本生成的自动保存提示。此次将共用的串行调用、输入映射和 mutation 发布留在 EditorSession，本地 LocalEditorSession 管理文件所有权与恢复，客户端 RemoteEditorSession 管理 HTTP、WebSocket、确认和重连。远端 core 从 host 的历史快照加入，只有 host 持有普通 FileSystem 并协调文件保存与外部合并。原有类和路径直接迁移，未增加策略包装层。

两份脏文档与持续恢复写入失败的实际 WASM 重现暴露了零延迟重试：批量 checkpoint 在首错立即返回，只清除了首份文档的期限，后续文档仍以 recoveryDelay=0 重新排队。现在一轮会尝试所有文档和目录意图，清除已尝试文档的期限，保留首个错误；某份草稿失败不阻止其他草稿落盘。原有单文档故障测试未覆盖这一组合，新增 core 与实际本地会话计时器回归。

既有容量规则也存在矛盾：规范化 LF 正文与物理文件共用 5 MiB 上限，但保存未限制 CRLF/BOM 编码后的字节。3.6 MB 的 LF 正文可成功保存成 5.4 MB CRLF 文件，随后写入草稿会使重启因基线过大而失败。此次保持正文上限，以两倍正文上限加 3 字节约束物理文本，并在解码归一化后再次验证正文；回归覆盖完整 5 MiB 正文经 CRLF/BOM 保存、重新打开、继续编辑和恢复。

移除历史 IO 后，编辑、撤销、导入和副本会话更新均改为同步调用；PendingWrite 的版本及 cursor 返回值不再携带没有实际空分支的 Option。纯 Rust 内存实例可直接使用 EditorCore::memory，默认 Infallible 仅表达没有 FS 值，不提供虚拟文件系统。WASM 内存入口合并为 EditorBinding.memory；无 FS 保存明确报 Unsupported，副本不生成本地保存计时。前端文件契约同时要求版本化读取和写入返回 revision，去掉桥接层的可选能力假设。

服务队列复核还发现，远端 checkpoint 等待确认和 resolve 的保存重试未像其他网络命令一样让出队列，慢网络期间会阻塞后续输入及入站更新。两者纳入既有 detached 调度，回归通过服务 scheduler 投递确认，覆盖成功、失败及派生预览失败不改变命令结果。发送队列的 ACK 直接处理，不依赖该 scheduler；flush、关闭和挂起不需要为此增加新的调度层。

随后复查发现，本地组合输入跨过自动保存期限时会消耗 timer，而 OPFS 在组合输入结束后不观察文件，也没有重新安排保存。组合输入结束现独立恢复保存调度，目录观察继续按能力启用。纯 stat、readDir、readFileSnapshot 原先无条件发布全部驻留正文，现不刷新；有正文副作用的文件操作通过 mutation 交付正文，只补相关元数据。原有每文档恢复 timer 还会在慢 IO 下排入多个全库 checkpoint，三份草稿可写九次；恢复调度改为会话级合并，显式 checkpoint 也暂停重复排队，并保留首次待写期限。

恢复错误属于 core 全局状态，保存、重新打开和观察核对均可能清除它，但原会话只更新当前文档。现在同步相关文档的恢复元数据，包括组合输入期间被排除观察的文档，以及先完成恢复、再因物理文件过大而保存失败的分支。独立复查还复现了慢恢复 IO 完成后重新创建已释放会话的 timer，释放标记现在阻止晚到发布与重新调度。

远端重连原先在握手结束前替换空同步队列，又在 core 替换后继续等待视图登记和导入启动推送，失败时可能丢掉旧正文、撤销或未确认屏障。现在先准备快照、视图和启动包，在 core 串行边界中检查连接有效性，并于成功回复时安装新会话与同步状态。提交前失败保留旧状态；native IPC 等待期间发生断线，只要 core 已提交，就返回新快照并保持离线，UI 不再无条件切回在线。提交期间的视图变化随后对账，晚到推送按新会话导入，后续失败不伪装成旧会话未变。

继续在真实 WASM、服务队列与客户端 RPC 之间延迟回复，复现了重连最后一次读取之后的推送丢失：core 已导入新正文，客户端却丢弃等待重连回复期间的事件，随后安装较旧快照，下一次增量立即触发投影版本不连续。原子替换成功后的 resident 或离线元数据读取失败，还会使已提交的新会话被报告为重连失败。现在重连只返回原子替换成功时的快照，并在同一 core 调用边界捕获事件序号；删除提交后的 resident 读取，不抑制普通文档通知，后续维护失败只改变连接状态。客户端每份已开文档最多合并最后一份完整正文和最后一份元数据，只将基线之后的状态叠加为最终快照，不重放其中单独一段 delta。

失败路径另有一个窗口：旧推送已在 core 中导入，但 IPC 回复尚未返回时开始重连；事件在重连准备失败前到达，客户端丢弃缓存便会丢失这份旧会话更新。等待期间现继续按原有投影规则处理事件，保留旧输入并完成 rebase；成功后才以新基线及后续状态清除旧输入和临时投影错误。真实回归同时保留乐观输入，核对准备失败后 UI 的本地输入与远端更新均存在。

独立复查又发现关闭标签与重连的交错：旧 release 已成功，UI 因 generation 改变而保留标签；若新替换紧跟在 release 的 core lease 后执行，订阅删除尚未运行，预先取得的候选快照还会把已关闭文档重新接入。外部删除并重建同一路径后，幽灵文档进一步导致新文件因路径冲突打不开。关闭成功现按同一 UI record 移除标签，退订表与视图在 release 的成功 lease 内同步更新，替换前裁剪已关闭的候选文档及对应 host、接收序号；旧 transport 在 lease 开始时失效则拒绝释放新会话。真实回归与独立复现核对 UI、订阅和 core 目录均为空，同路径新身份文件可重新打开。

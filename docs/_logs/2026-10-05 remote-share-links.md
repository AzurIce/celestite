# Remote 分享链接与访问权限方案

日期：2026-10-05。本文记录本次确定的链接模型、职责边界和实施方案；接口与存储结构为目标契约，尚未实现。不引用外部可变文档。

## 1. 目标与授权模型

远端连接只需一个 URL，URL 不包含真实 Vault 名称、配置 ID 或磁盘路径。访问权限赋予链接，持有链接即可获得对应权限，不要求账号或用户身份。

同一个 Vault 可以生成多份独立分享，每份分享具有自己的凭证、权限和生命周期。链接表示一份授权；持久化的 `vaultIdentity` 表示库和历史的身份。撤销某份分享不改变 Vault 身份，不影响其他分享。

首期权限为 `readonly` 和 `edit`，覆盖整个 Vault。编辑权限包括正文修改、保存和目录修改；创建、列出、撤销分享属于宿主管理能力，不随编辑链接授予。

## 2. 连接 URL 与 API

```text
https://host/<edit-key>
https://host/ro-<readonly-random>
```

连接 URL 到 key 为止，是客户端调用 API 的基址：

| 相对路径                                                 | 用途                                           |
| -------------------------------------------------------- | ---------------------------------------------- |
| `/api/v1`                                                | 连接描述、Vault / 历史身份、有效权限与协议能力 |
| `/api/v1/stat`、`/api/v1/directory`                      | 条目信息、目录读取与创建                       |
| `/api/v1/file`、`/api/v1/entry`、`/api/v1/rename`        | 文件读取、写入、删除与重命名                   |
| `/api/v1/documents/...`                                  | 文档查询、编辑、历史交换与保存                 |
| `/api/v1/events`、`/api/v1/documents/events`             | 持续事件订阅                                   |
| `/api/v1/sync`                                           | WebSocket 会话与同步                           |
| `/api/v1/preview/resources`、`/api/v1/preview/directory` | 沿用宿主已授权的只读预览资源查询               |

例如，连接 `https://host/ro-<random>` 后，目录请求发往 `https://host/ro-<random>/api/v1/directory`。WebSocket 使用相同基址，将协议转换为 `ws` / `wss`。部署路径前缀随基址保留，客户端不把请求重置到 origin 根路径。

客户端直接保存完整连接 URL，在其后追加 API 路径，不拆出单独 token，也不通过 Bearer、查询参数或 fragment 传递分享凭证。首期交互是粘贴链接连接 Vault；直接点击链接进入 Web 工作区的页面路由另行实现。

### `ro-` 前缀

`ro-` 方便人识别只读链接，同时属于完整 key：

- readonly 与 edit 分享各自从安全随机源生成 32 字节，使用无 padding 的 Base64 URL 安全编码。edit 生成值避开保留的 `ro-` 前缀；readonly 在独立随机值前加 `ro-`。
- 服务端计算完整 key 的摘要，包括 `ro-`，不剥掉前缀再查找。
- 删除、添加或修改前缀后的 key 没有对应授权，应访问失败。只读链接的随机部分不同时注册为编辑凭证。
- 权限以服务端分享记录为准。生成和恢复分享记录时校验格式与权限一致；客户端以连接响应提供的有效权限决定交互。
- `ro-` 表示分享授予只读权限。edit 分享仍可能受宿主的 Vault 级 `read_only` 限制。

链接规范化只处理连接基址的尾部斜杠，不改变 key 的大小写或内容。

## 3. 分享记录与持久化

```rust
enum Permission {
    ReadOnly,
    Edit,
}

struct Share {
    id: ShareId,
    key_hash: Hash,
    key_format: KeyFormat,
    vault_id: VaultId,
    permission: Permission,
    label: String,
}
```

`ShareId` 是用于管理的非秘密标识，不能代替 key 访问 Vault。`vault_id` 对应已有持久化的逻辑身份，不使用配置 ID、显示名称或文件路径。

每个 Vault 的私有 `state_dir` 增加独立的 `shares.redb`，由 `ShareStore` 管理 schema、Vault 身份绑定与分享记录。分享状态不进入正文 CRDT，不随正文历史压缩或普通文件保存变化。分享库沿用私有状态目录的范围与 owner 约束。

服务端恢复分享记录后，建立 `key_hash → ShareGrant → HostedVault` 索引；重复凭证摘要或 Vault 身份绑定不匹配必须报错，不猜测目标。`key_format` 保存凭证格式版本与类别，创建时检查实际 key，恢复时检查格式类别与权限一致，请求时同时检查实际 key 的格式；不能从不可逆摘要反推出原 key。

创建分享时先持久化记录，再发布索引并返回完整链接。原始 key 只在创建时输出，分享库仅保存摘要；列表展示 ShareId、标签和权限，无法重新构造原链接。遗失链接可以重新创建分享，并撤销不再需要的旧分享。

正常重启恢复原有链接；没有分享时不自动创建默认编辑入口。分享库缺失或损坏不自动补发凭证，初始化和恢复由明确的管理操作处理。

更改名称或配置 ID 保留分享。目录 / profile 迁移继续遵守宿主的身份和根目录迁移校验；恢复同一逻辑身份后才可恢复原分享。显式重置产生新 Vault 身份时，原分享不能自动指向新库。恢复旧备份也会恢复当时的授权状态，包括当时尚未撤销的分享。

宿主提供创建、列出、撤销的管理命令。首期分享权限创建后固定；调整权限通过创建新分享和撤销旧分享完成。本机管理通道的传输与认证在实现时具体确定，远端 readonly / edit 凭证均不能调用管理操作。

## 4. 网络授权与 core 边界

```rust
struct RemoteAccess {
    vault: Arc<HostedVault>,
    share: Arc<ShareGrant>,
}
```

HTTP 入口从路由提取完整 key，计算摘要、解析有效分享，再生成 `RemoteAccess`。业务处理函数通过该上下文取得 Vault，不直接根据外部路径查找配置 ID。

WebSocket 在 upgrade 前完成相同鉴权并确定 Vault。首帧保留协议版本、预期 Vault / 历史身份校验，不再携带 token；鉴权和身份校验通过后才建立同步会话、发送快照与订阅更新。

授权检查按操作语义执行，不能只根据 GET / POST 判断。以明确的操作分类替换网络入口中含糊的 `mutation: bool`，HTTP 与 WebSocket 共用读取和修改规则。

| 操作                                        | readonly | edit |
| ------------------------------------------- | -------- | ---- |
| 目录、文件、正文、快照与历史增量查询        | 允许     | 允许 |
| 打开文档、预览、读取已授权的 package 资源   | 允许     | 允许 |
| 持续接收正文更新、目录通知与心跳            | 允许     | 允许 |
| 编辑、导入客户端操作、撤销 / 重做、提交副本 | 拒绝     | 允许 |
| 保存、创建、移动、重命名、删除条目          | 拒绝     | 允许 |
| 主动重试宿主协调故障                        | 拒绝     | 允许 |
| 创建、列出、撤销分享                        | 拒绝     | 拒绝 |

有效编辑权限为 `分享权限 == Edit && !vault.read_only`。连接描述返回有效权限，UI 和客户端 core 同步限制编辑；最终检查由服务端执行，手工构造请求不能绕过。

只读约束针对访问者提交的修改，不禁止宿主内部运行：打开和查询可以完成必要的文档登记、缓存和磁盘观察；文件监听与自动协调仍能更新宿主历史并广播外部变化。core 不接收分享 key，也不承担分享管理，正文与历史业务继续使用已有契约。

分享限制不扩大文件或预览资源范围，资源读取继续沿用宿主已经授权的边界。写入请求中的文档 ID 必须属于上下文指向的 Vault。

## 5. 撤销与活动会话

每份运行时 `ShareGrant` 提供有效状态和撤销通知。HTTP 请求、WebSocket 会话及持续订阅都关联该授权，不永久复制一个脱离分享生命周期的权限值。

撤销持久化与操作准入通过同一授权的串行边界协调：撤销完成后不再接受新操作，排队请求在执行前重新检查；已进入提交过程的操作允许完成。持久化失败不得报告撤销成功。

成功撤销后移除凭证索引、使授权失效，并通知对应 WebSocket 和 SSE 流关闭。持续推送在发送前检查授权状态；已发送或已经被客户端读取的数据不被收回。撤销不影响其他分享或宿主自己的编辑与协调。

客户端将授权失效呈现为连接不可用，停止新操作并保留待确认正文，沿用已有导出和恢复边界，不自动切换到另一份更高权限的链接。

## 6. 客户端连接与实例

客户端持久化独立的 `connectionId`、完整连接 URL 和显示名称，连接成功后取得 `shareId`、`vaultIdentity` 与有效权限。打开和重连都重新验证身份与权限，本地缓存不能作为授权依据。

删除“描述响应 ID 必须等于 URL 最后一段”的校验。URL 最后一段现在是分享凭证，响应使用非秘密的分享 ID 和逻辑 Vault 身份。连接 URL 不承担本地实例 ID 的职责。

同一分享可以复用本地已打开的实例。不同分享即使指向同一个 Vault，也保留各自的授权、Worker、writer 和个人撤销会话；可以关联显示共同的 Vault 身份，但不合并权限或复用更高权限实例。

UI 移除单独的 token 输入，连接列表展示名称、服务器和有效权限，通过明确的复制操作取得完整分享链接。只读视图仍可显示正文、预览和实时外部更新。

## 7. 凭证与日志处理

完整连接 URL 是访问凭证，转发链接就转交权限。公网部署使用 HTTPS / WSS；本机开发可使用 loopback HTTP。

应用请求日志、错误信息和反向代理访问日志必须脱敏 key 段，例如 `/<redacted>/api/v1/documents/...`。诊断关联使用非秘密 ShareId，不记录原 key、完整连接 URL 或正文里的凭证。连接页面避免把完整链接用作 Referer，授权 API 响应使用 `no-store`。

客户端为重连保存完整链接，因此连接记录同样属于凭证存储；不自动进入项目设置、普通诊断导出或分享库文件树。

## 8. 实施阶段与验收

| 阶段               | 交付                                                        | 完成标准                                                                                                  |
| ------------------ | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| S1：分享状态与管理 | ShareStore、随机 key、摘要索引、宿主管理命令                | 同 Vault 多份独立分享；前缀与权限一致；持久化后才返回链接；重启恢复；撤销记录和身份绑定可验证             |
| S2：服务端网络入口 | 基址路由、RemoteAccess、HTTP / WebSocket 统一授权、订阅失效 | 认证后才访问 Vault；读取与修改按语义分类；所有写入入口拒绝 readonly；撤销影响活动会话与排队请求；日志脱敏 |
| S3：客户端接入     | 单 URL 连接、独立 connectionId、有效权限与失效交互          | 多分享连接同一历史并实时同步；实例权限不混用；只读预览正常；重连验证身份；待确认正文可恢复                |
| S4：迁移收口       | 调用方、测试、调试入口、示例与当前文档                      | 删除按配置 ID 连接的网络入口和单独连接 token 流程；无绕过分享授权的旧路由；格式检查及集成验证通过         |

验收至少覆盖：

1. 连接 URL 不包含 Vault 名称、配置 ID 或磁盘路径；部署前缀与尾部斜杠处理正确。
2. 同库 readonly / edit 使用独立随机值；移除或添加 `ro-` 均访问失败；篡改客户端权限不能写入。
3. readonly 能打开文档、获取快照 / 增量、订阅实时更新和预览，但不能通过文件、文档、副本提交或 WebSocket 入口修改内容。
4. edit 正常编辑和修改目录；Vault 级只读限制生效；跨 Vault 文档 ID 不能越权。
5. 多份分享返回同一 Vault 身份，客户端分别维护实例；撤销其中一份不影响其他分享。
6. HTTP、WebSocket 和 SSE 在撤销后按约定失效；排队请求和正在提交的操作遵守明确的准入边界。
7. 重启保留有效链接及撤销结果；改名保留授权；新身份、损坏分享库和缺失状态不会静默接入旧链接。
8. 普通日志、错误、连接列表和诊断导出不泄露 key；旧路由及 token 调用方完成迁移。

文档与示例迁移保留日志的日期快照；当前架构和路线图只维护目标边界、阶段与完成标准。单文档 / 子目录分享、账号权限、编辑链接管理分享、在线修改分享权限和直接点击链接进入工作区不属于首期范围。
